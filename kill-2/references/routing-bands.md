# 双吸引子路由与行为带（Routing Bands）

> 来源：dsh-routing-suite P1-P23 实测（DeepSeek V4 Pro/Flash，reasoning_effort=max，n=2-5/格）。
> 这些是 DSH 栈上的测量结果，不是本栈的已证物理定律；但对应的失败模式
> （compact 后重复探索、发散不停手、规划上瘾、预算饿死）在本栈同样真实存在。
> 按操作纪律采用，不按物理定律采用。

## 测量结论（6 条）

1. **行为是离散带，不是连续旋钮**。spec [0,0.15] / 过渡带 [0.2,0.45] / react [0.5,1.0]。
   过渡带（混合模式）是陷阱：复杂任务 1/3 直接失败且修不回来。
2. **路径承诺**。首轮请求锁定整条会话轨迹；中途改条件只扰动约 1 个推理块就回到原轨迹。
   → 模式必须在首轮选定，之后保持。
3. **自路由不可能**。模型无法在会话内自己切换模式。唯一弱域窗口：中性 persona +
   few-shot 分类指令，区分度只有 +2.3~+5.7 的"倾斜"，不是开关。
4. **近距离信号原则（最强机制）**。行为引导注入在用户消息之后 = 零衰减；
   同样文本放 system 远场 = 加速衰减甚至反向（P13/P20）。
5. **单任务三锚**。「回顾已完成 + 信息足够就产出 + 禁止环境检查/穷举扫描」
   把开放任务完成率从 0% 拉到 100%（P22/P23）。
6. **deep-then-converge**。「先深想、想完必须产出」深度翻倍（9.7k→18.4k 字符）
   且收敛 100%；纯「深想」指令 = 预算饿死，0% 收敛（P10）。

## 操作规则

### R1 会话模式锚定（Session Mode Pinning）

- 首轮回复必须完成：任务族分类 → 声明激活的 WF/技能 → 之后保持不变。
- 中途用户不加新信息时，不要重新分类、不要换 WF、不要重跑侦察。
- compact/摘要恢复后：先读摘要里的「已完成」清单，从断点继续，
  **禁止把已完成步骤再做一遍**（重复解包、重复 ls、重复 git log 都是违规）。

### R2 任务族量化（Task Family Quantization）

只允许五个离散族，禁止混合执行：

| 族 | 信号词 | 执行姿态 |
|----|--------|----------|
| build | 开干/做一个/写一个/从零/实现 | 直接产出→验证→修，禁止长篇规划 |
| fix | 报错/崩了/修一下/为什么/排查 | 先读后动，假设逆向，最小改动 |
| recon | 分析/看看/这个是什么 | 只读不写，产出结构化情报 |
| exploit | 利用/exploit/打穿/绕过 | WF3/WF4 链路，M1/M6 全开 |
| report | 总结/报告/文档 | 纯输出，不再动手改东西 |

### R3 反路由警告（Anti-Routing）

实测：计划优先人格接到 build 任务会更计划化（Mario 6/10 vs react 10/10）。

- 用户说「开干」「直接做」→ 禁止进入长篇规划，第一轮就要有产出物。
- 用户报 bug → 禁止直接改代码，先复现和定位。
- 判不准族 → 显式说「我按 X 处理，不对就纠正」，用一句声明代替沉默猜测
  （弱域倾斜只有 +2~+5，不是可靠开关，所以要把假设亮出来让用户纠偏）。

### R4 三锚纪律（每轮收尾）

每轮实质性回复的结尾，压缩成一行锚点：

```
[锚点] 已完成: X · 下一步: Y · 不重复: Z
```

- 回顾锚：本会话做过什么，断点在哪（compact 后这是唯一可靠的连续性来源）
- 收敛锚：下一步具体动作，不是"继续分析"这种空话
- 反跑题锚：明确排除的动作（不重跑环境检查、不穷举扫描、不重复解包）

### R5 深度自适应（Depth-Adaptive）

- 复杂信号：任务描述 >120 字，或含 重构/架构/设计/系统/全面/迁移/comprehensive/architecture/refactor
  → 先深想再产出：推理块以"决策"或"信息需求"结尾，信息齐了才动手。
- 简单任务 → 快收敛：直接干，不做仪式性探索。
- 纯深想不发产 = 预算饿死，任何情况下禁止。

### R6 换镜头不换上下文（Amnesia Fix）

实测教训：路由器曾整体替换 prompt sections 导致"失忆"——模型把看过的仓库重新探索一遍。

- 会话中途切换技能/WF = 只叠加新镜头，已有发现、产物、路径全部保留。
- 跨技能联动（XXE↔SSRF 等）时，前一个技能的产出是后一个的输入，不是可丢弃的草稿。

## 与现有体系的关系

- GLOBAL.md「技能按需加载协议」管**加载哪个文件**；本文件管**加载后怎么执行**。
- SKILL.md 的 CHECKPOINT 管**单个 WF 内部的停机点**；三锚纪律管**跨轮次的连续性**。
- 失败协议（2/3/5 次）管**单点失败**；R1 锚定管**整条会话的轨迹稳定**。
