# Impeccable 设计系统

从 [pbakaus/impeccable](https://github.com/pbakaus/impeccable) 引入，17 个设计命令 + 前端开发完整参考库。

## 使用方式

直接说 `impeccable <命令> [目标]`，按以下步骤执行：

1. **解析命令** — 匹配命令清单；失败走异常表兜底
2. **加载子技能** — 读取 `skills/impeccable/<命令>/SKILL.md`；缺失回退 frontend-design
3. **🔴 上下文确认** — 目标模糊时反问受众/场景，禁止无上下文动手
4. **执行子技能流程** — 按子技能 numbered steps 逐行执行
5. **输出交付** — 可运行代码或结构化报告

```
impeccable distill 这个页面        → 简化布局，去芜存菁
impeccable audit 弹窗组件          → 审计可访问性/性能/主题/响应式
impeccable colorize 导航栏         → 给设计加配色
impeccable critique 这个设置页      → UX 批评
impeccable frontend-design 做一个定价卡片 → 前端组件开发
```

## 命令清单

| 命令 | 作用 | 适用场景 |
|------|------|----------|
| `adapt` | 跨设备/跨平台适配 | 移动端适配、响应式 |
| `animate` | 加动效、微交互 | 按钮反馈、转场动画 |
| `audit` | 全面界面审计 | 上线前检查：可访问性、性能 |
| `bolder` | 增强视觉冲击力 | 界面太素、太安全 |
| `clarify` | 改进 UX 文案 | 报错提示、微文案、标签 |
| `colorize` | 加配色 | 黑白灰太多，缺品牌色 |
| `critique` | UX 批评 + 可操作建议 | 功能评审、设计走查 |
| `delight` | 加惊喜感 | 空状态、加载、成功反馈 |
| `distill` | 简化为本质 | 页面太复杂、信息过载 |
| `extract` | 提取可复用组件 | 建立组件库、规范化 |
| `harden` | 加固边界 | i18n、文本溢出、错误处理 |
| `normalize` | 对齐设计系统 | 保持一致性 |
| `onboard` | 新手引导、空状态 | 首次体验、功能引流 |
| `optimize` | 性能优化 | 加载速度、渲染、动画性能 |
| `polish` | 上线前最后打磨 | 对齐、间距、细节 |
| `quieter` | 降低视觉强度 | 太跳、太花哨 |
| `teach-impeccable` | 一次性项目设定 | 首次使用建立设计基线 |

## 参考库

`frontend-design` 附 7 篇深度参考，执行时会自动引用：

- **配色与对比** — 无障碍色彩系统
- **交互设计** — 手势、反馈、状态
- **动效设计** — 曲线、时序、叙事
- **响应式设计** — 断点、容器查询
- **空间设计** — 间距、节奏、布局
- **排版** — 字体、层级、可读性
- **UX 写作** — 语调、简洁、一致性

## 设计哲学

**极端风格 > 中庸** — 带着目的：先确认受众/场景，再产出可用的代码（不是设计稿）

## 输出规范

每次设计输出必须包含：
- 设计方向说明（选了什么风格，为什么）
- 可运行 HTML/CSS 代码（含浅/深色适配）
- 配色标注（每色附 AA 级对比度值）

## 异常与边界条件

| 触发条件 | 一线修复 | 兜底 |
|----------|----------|------|
| 未知子命令 | 模糊匹配（`dist`→`distill`），提示最近候选 | 列出 17 个命令重选 |
| 上下文不足 | 反问受众/场景再动手 | 用通用 Web 后台默认继续并标注假设 |
| 子技能 SKILL.md 缺失 | 回退 frontend-design 通用流程 | 提示不可用，推荐备选命令 |
| 依赖参考文件缺失 | 跳过该参考继续 | 标注缺失，不影响核心 |
| 超出 UI 设计范围 | 能力内提供建议并标注越界 | 转其他 skill |

**🔴 CHECKPOINT** — 禁止静默跳过异常。一线修复后仍失败再兜底。

## 反例与黑名单

- **不要 AI 味** — 灰白渐变、玻璃态、紫光暗黑、通用卡片网格。参考 frontend-design DON'T 清单
- **不要单方案** — 至少 2 个设计方向
- **不要跳过 accessibility** — 配色必须标注 AA 级对比度
- **不要假设终端** — 代码须同时适配浅/深色模式
- **不要空话判断** — 禁用"灵活应用/根据情况/可以考虑"
