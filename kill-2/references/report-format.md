# 报告与输出格式基线（Report Format Baseline）

> 来源：shan-skills（Baijidot/shan-skills v2.0）三零件收编。只收格式件，不收输出风格。
> 文言输出/强制压缩风格**未采纳**——与「直接不废话」重叠且交付物需完整句子。

## 1. 四色行级 Review 格式（shan-review 收编）

代码审计、补丁审查、diff 确认时的统一行级标记。源自 shan-review，扩展了红队语境。

```
L42: 🔴 bug    user 或 null 解引用 → crash。加 if(!user) return。
L58: 🟡 warn   输入未过白名单直接拼 SQL，可注入但需前置条件。
L73: 🟢 nit    命名 x1 不达意，宜改 targetHost。
L88: 💡 sug    此处可加缓存，命中率约70%。
```

规则：
- **只标出问题的行**，不出全文转写。行号跟随文件当前版本，跨版本引用需注明 commit。
- 🔴 = 确证缺陷/可直接利用；🟡 = 条件性风险；🟢 = 风格/可维护性；💡 = 增强。
- 每行结论 = 标记 + 问题 + 修复建议三段式。禁止只标不修。
- 红队语境：🔴 = confirmed exploitable / 🟡 = requires conditions / 🟢 = hygiene / 💡 = attack surface suggestion。
- 一图胜千言：行号标记与截图/POC 引用并用时，写 `L42: 🔴 ... （见 POC #3）`。

## 2. 上下文压缩摘要模板（/善compact 收编）

长会话手动续命、跨沙盒搬运上下文、compact 后恢复锚点时使用。五段式：

```
# 对话摘要
## 任务
[一句话：目标是什么]
## 已做
[分点：已完成动作 + 产物路径]
## 关键代码/命令（原样）
[代码块/命令/路径，一字不改]
## 待解
[分点：未闭环的问题]
## 技术要点（原样）
[版本号/配置值/报错原文/哈希/commit]
```

- 摘要全文 ≤300 字（代码/命令/技术要点不计入）。
- 「原样」段落的铁律：代码、报错、路径、URL、版本号、配置值、Git 标识一字不改。
- 与 Minis 自带 compact 的关系：自带 compact = 系统级无损摘要（工具调用完整保留）；
  本模板 = 用户级定向摘要，用于**手动**压缩和跨沙盒搬运。两者互补，不互斥。
- 恢复会话时：先读「已做」清单，从「待解」第一项继续，禁止重做已完成步骤（R1 锚定的应用）。

## 3. 三档压缩基线（压缩理念收编）

输出密度参考值，不强制文言，用于评估自己的输出是否够紧凑：

| 档 | 目标压缩率 | 适用 |
|----|-----------|------|
| 🪶 Lite | 30-40% | 对外解释、新接触话题的破冰 |
| 🪨 Full | 50-65% | 日常技术交流（默认基线） |
| 🔥 Ultra | 65-87% | 快速确认、状态回报、内部交流 |

- 判断标准不是字符数，是「无一字可删」：回复中不存在可删而不损义的字。
- 实测边界（本栈验证，2026-08-22 三样例盲测）：文言 vs 压缩白话，
  字符再省 23-31%，但 token 数持平（分词器把文言单字切成更碎片段）。
  → 真实收益在**单 token 信息密度与注意力权重**，不在 token 数量。
- 适用边界：交付物（客户报告、issue、PR 描述、commit message）不套用压缩基线，用完整句子。

## 4. 公开仓库提交纪律（shan-commit 精神重构版）

> 触发场景：仓库必须公开（gh run / Actions 免费额度），但 commit 历史暴露攻击链。
> MinisFix 项目实锤：详细 message 曾把样本名/攻击链写进公开历史，被迫消耗数轮做仓库伪装。

规则：
- **公开仓库 message 一律中性**：`chore: update`, `fix: build`, `v2.56.15` 式无信息量提交。
  详细意图写在**本地 commit 之后再 soft-reset 改写**，或落到 memory 日志/私有 notes——不进公开历史。
- Conventional Commits 前缀可用（chore/fix/feat），但 scope/subject 不携带目标名、漏洞类型、
  样本名、工具链细节。`fix(auth): token expiry` 这类含技术语义的 scope 也不行——在红队仓库
  语境下等于自报家门。
- 一切带语义的交接（改了什么/为什么）走 **memory 日志 + 私有 references 文件**，
  公开历史只留版本号/构建号级别的裸时间线。
- 本地详注法：`git commit -m "chore: build"` 之前，把真实意图先写进当日 memory——
  公开层与私有层彻底分离，公开历史=发布时间线，私有层=真实工程日志。
- 私有/内部仓库不受此约束，正常写详细 message 保持工程可维护性。
