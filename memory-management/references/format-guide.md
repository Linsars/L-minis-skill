# Memory Entry Format Guide

## Standard Format

Every memory entry follows this structure:

```
- [P0-2][YYYY-MM-DD][src:user|infer|system] content (≤80 chars)
```

## Priority Levels

Understanding priority helps you decide where information lives and how long it persists.

### P0: Core Identity (MEMORY.md only)
Permanent characteristics that define how you work with this user. These never expire and don't need dates.

**Examples:**
- `[P0] Prefers conclusions first, then supporting details`
- `[P0] Python: use type hints, avoid global state`
- `[P0] Never send unsolicited external messages`

**Why P0?** These are foundational truths that apply across all projects and sessions. Getting them wrong would fundamentally break the collaboration.

### P1: Active Context
Current project decisions, ongoing preferences, and architectural choices. These stay relevant for weeks or months.

**Examples:**
- `[P1][2026-03-10][src:user] ProjectX uses PostgreSQL with RLS policies`
- `[P1][2026-02-28][src:user] Prefers detailed error messages during debugging`

**Why P1?** This information actively shapes your current work. It's frequently accessed via memory_search and appears in MEMORY.md's Active Projects section.

### P2: Temporary Notes
Bug fixes, one-time events, short-lived reminders. These typically expire after 30 days if not accessed.

**Examples:**
- `[P2][2026-03-14][src:system] Fixed CORS issue by adding credentials:true`
- `[P2][2026-03-12][src:infer] User seemed frustrated with slow build times`

**Why P2?** Useful in the moment but not worth cluttering long-term memory. If a P2 entry gets accessed frequently, it gets promoted to P1.

## Source Attribution

The source tag indicates information reliability, which matters when resolving conflicts.

### src:user (Highest Trust)
The person explicitly stated this. Always wins conflicts against infer/system.

**Example:** User says "I want all API responses in JSON" → `[src:user]`

### src:infer (Medium Trust)
You inferred this from context or behavior patterns. Might be wrong.

**Example:** User repeatedly asks for verbose logs → `[src:infer] Prefers detailed logging`

**Why lower trust?** Inference can misread situations. Maybe they only wanted verbose logs for that one debugging session, not permanently.

### src:system (Mechanical)
Auto-generated by scripts (memory-eviction.js, hit-tracker.py, etc.) or by memoryFlush.

**Example:** `[src:system] Compressed 2026-03-01.md → compressed/2026-03-01.md`

## Special Cases

### P0 entries omit dates
```
- [P0] Response style: concise, no fluff
```

Not:
```
- [P0][2026-03-15] Response style: concise, no fluff
```

**Why?** P0 entries are timeless. Adding a date implies they might expire, which contradicts their permanent nature.

### Conflict markers
When entries contradict and need user review:
```
- [P1][2026-03-15][src:user][CONFLICT:needs-review] Prefers short responses
```

### Superseded entries (in archive)
```
- [P1][2026-01-10][src:user] Uses PostgreSQL [SUPERSEDED 2026-03-15: migrated to CockroachDB]
```
